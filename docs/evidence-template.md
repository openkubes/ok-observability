# Evidence Template — Jira Comment Pattern (OK-100 baseline)

Evidence of acceptance in OpenKubes is recorded as a **Jira comment** on the
implementing ticket (pattern established in OK-15/OK-60). This template is the
baseline the OK-100 spike evaluates; `make evidence` generates a filled
instance automatically. No parallel acceptance model — this extends the
existing acceptance and release-tag discipline.

The spike's open question (Research Question 5): does a generated file, CI
output, or PR summary add value **beyond** the Jira comment? Until answered:
the Jira comment is authoritative, the generated file is a convenience.

---

## Template

```markdown
**Verification evidence — ok-observability**

- Date: <YYYY-MM-DD HH:MM UTC>
- Commit: `<short-sha>` on `<branch>`
- Ticket: <OK-nnn>
- Performed by: <human> (with AI assistance: yes/no)

| Check | Result |
|---|---|
| `make verify` | PASS / FAIL |
| `make conformance` | PASS / FAIL |
| Deployment step (if applicable) | PASS / FAIL / n/a |
| Production acceptance criteria (if applicable) | PASS / FAIL / n/a |

<For FAIL: relevant output and follow-up ticket reference.>
<For conformance: cluster/environment the gate ran against.>

_Generated by `make evidence`, reviewed and posted by a human._
```

## Rules

- A human reviews and posts the comment. Evidence generation may be automated;
  evidence **assertion** is not.
- FAIL results are evidence too — post them. Never rerun-until-green without
  documenting what changed.
- Release tags follow the existing discipline: set when ADR Accepted +
  Implementation Profile + Provider Values operational — not at commit time,
  and not implied by a green evidence comment.
